# State machines

A map of the flows in the app (`apps/desktop`) and the SDK (`packages/sdk`) that move through steps, so a developer or
an agent finds where a flow lives and what it can be in, without reading it all. The rules are in
[module-rules.md](module-rules.md#4-behaviour) ("One value per flow") and the State section of `CLAUDE.md`.

- **One value**: a flow keeps its state in one union (`status`, `phase`, `step`), never in flags that can disagree.
- **Work a view waits for**: `useTask` (`@tavora/official-ui/use-task`): `idle | running | failed`, always ends, drops an
  answer that is no longer the newest.
- **Dialogs in the slot** (renderer `host.ts`): after an `await`, a dialog closes itself with `closeDialog(request)` and
  goes on to the next one with `followDialog(from, next)`, so whatever the user opened meanwhile, or a question that came
  up, stays.
- **Closing a kit dialog** (`modules/shared/src/components/ui/dialog/dismissal.ts`): each try (Escape, a press outside,
  the X) is `close`, `ask` (not `dismissible`: `dismiss-attempt` tells the page, which decides) or `refuse` (`busy`:
  refused without a word, `busy` winning). `dismissVerdict` is the step, with tests.
- **Real transitions** get a pure step function over the union, with tests (`dockDragStep` in `renderer/dock-drag.ts`).
- **Seen from outside**: the value goes on the view's root as `data-status` (`data-gesture` for a gesture), for tests and
  tools. `ModalDialog`'s `status` prop puts it on the dialog.

Update this page in the pull request that adds, removes or changes a flow.

## Still implicit

Flows that still keep their state in several fields, most used first, with the plan for each. Take one off the list in
the pull request that makes it explicit.

- **The overlays' crash breaker** (`main/game-overlay-service.ts` `crashes`, `stopped`, and the card's `cardCrashes` in
  `main/game-layer-windows.ts`) → `healthy | crashed | stopped` per window.

- **Host overlays over panels** (renderer `host.ts` `overlayOpen`, `panelsOut`, `heldPopups`, timers, with the
  requests in `overlay-area.ts`'s `PopupWatch` (`measureStep`, `answerStep`, `askAllStep`, tested), which also decides
  which panels a popup covers and how long a closing dialog holds; main `panel-views.ts` `overlayOpen`,
  `overlaySession`, `wanted`, `out`, `picturing`, `overlayPictures`, `standIns`, `inSight`, `prepared`;
  `overlay-canvas.ts`) → the overlay as `closed | partial(panels) | all`, each panel as
  `live | picturing | out | settling` (its picture stays until it has drawn and turned solid; a panel back from another
  tab goes through `settling` on its last picture too), with a step function, and `data-status` on `<html>`.

- **Workspace opening cover** (`main/host.ts` `openings`, `panel-views.ts` `openingState`, `panel-cover.ts`) → one
  opening with its own token: `waiting-for-data | covering | idle`.

- **Toast page health** (`main/toast-view.ts`: `ready`, `broken`, `fallback`, `retried`, `attempt`) →
  `loading | ready | retrying | down` with a step function.

- **Panel slot content** (`components/workspace/PanelContent.vue`: a 9-way `v-if`) → a pure `panelSlot(panel)` union
  and `data-status` on the slot.

- **Panel dialog** (`components/PanelDialog.vue`, `main/panel-views.ts` `dialogState`) → `closed | placing | drawn | shown`.
  A menu of the panel over its dialog is already one value (`dialogMenu`: `null | picturing | out`): the view steps aside
  behind its picture (`dialogPicture`) while the host page draws the menu.

- **Browser panel** (`main/browser-view.ts`: `status`, `error`, `committedUrl`, `requestedUrl`) →
  `blank | loading | page | failed | crashed`. `failed` also holds a page's own move to a site of the other session
  (`otherSession`) until the user opens it or stays (`openAsked`, `stay`); while it asks, redirects to the other session
  don't count, and other failures and the page's own commits don't replace it. How the navigation under way started is already one union
  (`navigationStart`: `user | page | restored`, with `crossSessionStep` as its step and tests; `restored` is the saved
  address `reopen` loads, Reload, Back, Forward and Try again, whose redirects to the other session ask); `ownNavigation` marks Tavora's own
  load, with its start, until Chromium reports it (or the load stops or fails first). `committedChosen` says whether the user chose the
  committed page's very address (a `user` start that ended where it began, no pushState since): when a site list changes
  (`siteSettingsChanged`), that address loads again in the other session, any other page loads its site's home. While the
  panel asks nothing moves; Stay checks again. A page's navigation carried to the other session keeps its `page` start.

- **Window visibility** (`main/host.ts`: `windowHidden`, `windowBehind`, `windowClosed`) → `front | behind | hidden | closed`.

- **Press windows** (`main/module-view.ts` `Press`, `browser-view.ts` `lastGesture`, tooltips) → one `GestureWindow`.

- **Gestures** (`WorkspaceRail` resize, `LayoutCanvas` drag and band, `WorkspacePage` panel drag) → one `gesture` union
  each, ended by blur too, with `data-gesture`. The rail and the canvas run on `bindDrag`, whose `phase` is that
  union's start; what each drag holds (`dragWidth`, `drag`, `band`) is still kept beside it.

- **System info worker** (`main/system-info-thread.ts`): one timer for two meanings → `none | running | idle-stopping |
